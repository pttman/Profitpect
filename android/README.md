# 小账岛安卓版

## 0.3 付款页面自动识别

新增 `PaymentPageService`。用户在系统手动授权“小账岛付款页面识别”，并在小账岛“设置付款识别”中开启“自动识别付款成功页”后，微信、支付宝前台的付款成功页可触发识别，无需付款通知。系统授权与产品开关均默认为关闭，付款页面与通知识别使用独立开关。

实现只读取无障碍节点文字，在本机匹配独立的“付款成功/支付成功”标题、终态操作、商户标签和唯一的人民币金额。不会点击、输入、执行手势、截屏、上传页面内容，也不处理密码输入、聊天、交易详情和历史账单页。不请求手势或截屏能力。页面文字不可读或模板不符合条件时不猜测金额，状态在设置中显示。当前没有 OCR 截图回退；实际平台版本和页面结构需真机样例适配。

默认进入“待确认付款”。用户可单独开启页面自动入账，但只有交易号可用、分类明确且不疑似重复时才自动入账；无交易号时必须人工核对。交易号可与通知识别跨渠道去重；页面保持不变期间仅处理一次。缺少交易号、重复打开旧结果页、服务重建等仍可能产生待核对项，不应视为完整流水。系统设置中撤销授权或应用内关闭页面识别后停止读取。

无障碍权限是系统级能力，应用的用途限制并不缩小系统授权本身。授权前应用展示用途说明；若系统限制安装来源或授权，需用户自行按系统允许的流程处理，不用 adb 代授予或绕过限制。

付款页面解析另有 18 条 JVM 断言，覆盖拆分金额节点、微信/支付宝字段、聊天/历史/密码/退款/转账/外币/多金额排除。下方 0.2 通知功能继续作为可选入口保留。

版本 0.2，Android 8.0（API 26）及以上。复用 React 界面，以原生 `NotificationListenerService` 在应用退到后台后识别付款通知。本版本为可安装的调试包，需要真机验收后再发布。

## 构建与安装

Windows 安装 Node、JDK 和 Android SDK（platform 35、build-tools 35 或以上），设置 `ANDROID_HOME`。

```powershell
npm ci
npm run android:build
```

输出 `android/build/xiaozhang-debug.apk`。构建脚本使用 SDK 自带的编译、打包及签名工具，不需要下载 Gradle；同时提供 Android Studio 工程。先运行上述脚本生成页面资源后，也可以从 Android Studio 打开 `android/` 构建。调试签名保存在被 Git 忽略的 `android/build/debug.keystore`，同一安装升级时需保留此文件。正式分发应使用独立的发布签名。

## 开启付款记账

1. 安装并开启正式账本；网页版账本不会自动迁移，可先导出 JSON，再在安卓包内恢复。
2. 右下角悬浮按钮轻点打开当前记账方式，长按 480 毫秒展开手动、AI、付款识别选项；小箭头支持普通点击和键盘操作。选择付款识别，再轻点打开设置。
3. 在“我的口袋 → 安卓付款记账”进入系统通知使用权设置，由用户主动授权“小账岛付款识别”。系统授权允许应用接收通知，本实现仅处理白名单应用、支付服务标题和付款成功文本，不保留其他通知。
4. 回到应用开启“收集付款通知”。默认先进入待确认列表，不直接入账。
5. 可主动勾选自动入账；商户、金额、分类都能确定且未发现疑似重复时才自动保存。
6. 可随时关闭收集、自动入账，或在系统设置撤销通知授权。停止收集后已有待确认记录仍可处理。

通知及解析结果只在应用私有存储中处理。不读取短信、剪贴板、聊天历史，不使用无障碍服务，不上传通知正文。原始通知文本不持久化；保留商户摘要、金额、日期、来源和散列去重标识。

## 规则、去重与持久化

- 来源包名限定微信 `com.tencent.mm` 与支付宝 `com.eg.android.AlipayGphone`，再限定支付服务通知标题；汇总通知和普通聊天标题不处理。
- 需要明确的付款成功方向，以及唯一的人民币金额。失败、取消、待支付、收款、退款、转账、红包、还款、外币和含多个金额的通知不入账，也不根据含糊文本估计金额。
- 以“订单号（存在时），或通知键与交易时间”的 SHA-256 标识去重；同金额同日且创建时间相距 5 分钟以内的已有支出，转人工核对，避免补记与通知冲突。两条不同且无订单号的通知仍可能无法自动确认是否同笔。
- 分类未知或疑似重复进入待确认列表；最多 200 条，满后显示错误并要求核对原始流水，不覆盖旧记录。
- 原生后台与网页桥接使用同一锁与 `SharedPreferences.commit()` 事务保存账本、待确认队列和处理标识。前端通过期望原文检查并发，不覆盖通知服务刚写入的账本；保存失败不显示入账成功。
- 账单保留来源；手动修改和删除仍可使用原账本功能。删除、忽略或撤销已处理付款后不会因相同通知再次投递而自动复活。
- JSON 备份包含正式账单及付款去重标识；系统授权、通知收集开关、待确认队列与设备级处理缓存不随备份恢复，用户需单独检查待确认记录。
- 当前日期按 Asia/Shanghai。账本存在应用私有存储，系统自动备份禁用；卸载、清理数据前需主动导出。

## 云端 AI

默认本机规则识别可离线运行。云端 AI 通过项目的 Node 服务接入 OpenAI Responses 结构化输出，配置见主 README。为安卓包设置构建环境 `VITE_AI_ENDPOINT=https://你的域名/api/recognize` 后重新构建；证书必须有效，密钥仅放服务器。未配置时会明确提示本机识别。只发送用户主动输入的单笔描述，不发送付款通知或历史账本。

## 已验证和待验证

已完成 Java 编译、DEX/APK 打包、签名校验、付款解析规则 JVM 测试，以及网页业务测试。2026-11-10 在用户连接的安卓手机（Android 17 / API 37）完成 34 项真机断言：实际 WebView 渲染、移动端宽度、原生桥接、AI 草稿、隔离账本原子保存、待确认、自动入账、去重、暂停、并发快照拒绝、进程重启恢复和测试数据清理。未向用户正式账本写入测试记录。用户系统通知授权及服务绑定已验证；真实微信/支付宝付款通知端到端仍待实际付款样例验证。

真机发现并修复 Windows `aapt2 -A` 将嵌套资源写成反斜杠 ZIP 路径的问题，现由 `jar` 写入网页资源，并在每次构建时检查 `assets/web/index.html` 及全部路径分隔符。系统栏边距由外层原生容器处理，避免新 Android 版本强制全面屏时覆盖网页。

付款页面解析已通过 18 项 JVM 断言，尚未完成真实支付页面端到端验证。当前 vivo / Android 17 真机出现无障碍授权短暂开启后被撤销的现象；系统启用服务列表的最近写入来源曾为 `com.vivo.safecenter`，无同期小账岛崩溃记录，具体触发策略仍需确认。系统快捷浮窗只负责切换服务，出现浮窗不代表服务持续开启。页面存储真机测试在授权检查处失败，不能计入已通过断言。排查授权持续性时不要运行会重启目标应用的 instrumentation，以免混淆返回设置页与进程重建的影响。

真机验收需包含：授权往返、关闭授权、前台/后台/进程重建后的识别、微信和支付宝实际通知样例、同通知重复投递、两笔同金额交易、手动补记后通知、低存储、备份保存/取消及恢复、撤销与后台写入冲突。支付平台版本、通知开关及厂商后台限制会影响覆盖率；平台未发送通知时无法识别，不能视为完整流水同步。通知标题与模板变化时需更新匹配规则，不应盲目放宽方向判定。
