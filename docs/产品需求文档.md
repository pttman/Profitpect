# 小账岛｜产品需求文档

> 2026-11-10 更新：按最新产品方向补充 0.2 智能记账和安卓付款识别。自然语言输入生成可修改、确认后入账的单笔草稿；本机规则与可选云端 AI 明确区分。安卓端由用户主动授予通知使用权，仅处理微信/支付宝明确付款成功通知，默认待确认，可另行开启符合条件时自动入账。提供去重、来源、暂停与撤销授权入口。网页版不监听系统付款通知，退款/转账不自动记成普通支出，不承诺获取完整流水。右下角悬浮记账入口支持轻点使用、长按切换方式，图标统一为高饱和多色组件。具体实现和真机验收范围见 `android/README.md`，本更新优先于下文 0.1“不接支付平台”的旧版范围描述。

## 1. 产品方向

### 1.1 我们要解决什么

用户想知道钱花在哪里，却常常被输入、分类和坚持记录的成本劝退。单纯把账记下来，也未必能让用户理解自己的生活。

以上是本方案的待验证假设，并非已经完成用户研究的结论。首版优先验证三个问题：

1. 用户能否在没有教学的情况下完成第一笔记录？
2. 用户是否愿意在消费后，或者每天空闲时主动回来补记？
3. 用户能否通过一个页面回答“本月花了多少，主要花在哪里”？

### 1.2 “好用”和“有趣”的具体含义

| 方向 | 必须做到 | 具体设计 |
| --- | --- | --- |
| 记得快 | 高频记录只输入必要信息 | 金额、分类即可保存；日期与账户有默认值；支持常用模板 |
| 找得到 | 记录可以轻松查找和修正 | 按日期查看，搜索备注，筛选分类和账户，随时编辑与撤销 |
| 算得对 | 明细、余额、预算和统计口径一致 | 区分支出、收入、转账、退款；明确跨月处理规则 |
| 看得懂 | 数据能回答生活问题 | 先展示本月净支出和预算，再展示分类与趋势 |
| 有反馈 | 每次记录得到轻量回应 | 简短确认、小岛局部变化、可跳过的月度故事 |
| 无负担 | 漏记、超支和关闭趣味功能都不会受到惩罚 | 不掉级、不清零、不用羞辱性文案；趣味模式随时关闭 |

### 1.3 产品取舍

第一版把“轻松记清日常收支”做完整。趣味承担陪伴和反馈的作用，避免增加一次记录的操作。

- 每次保存先落账，再播放反馈；动画不阻塞下一笔操作。
- 账单、金额与预算始终比装饰更醒目。
- 小岛成长只与记录习惯有关，消费金额越高不会得到更多奖励。
- 不强制注册，不通过广告打断记账。
- 不要求用户每天花钱；零消费日可以没有账单。

## 2. 用户与场景

### 2.1 首批目标用户

以个人消费为主，希望了解每月去向，但不想维护复杂财务体系的人。包括刚开始独立管理生活开支的学生与上班族。

这是一组设计假设。首批验证不按年龄刻板划分，优先寻找“有记账意愿、曾因麻烦而中断”的用户。

### 2.2 典型场景

| 场景 | 用户目标 | 需要的体验 |
| --- | --- | --- |
| 买完早餐或坐完地铁 | 趁还记得，快速记一笔 | 打开记录面板即可输入金额，单手操作 |
| 晚上补记一天 | 连续录入几笔，不反复进出页面 | 保存后可继续记，保留明确的日期和账户状态 |
| 月中查看花销 | 知道目前花了多少、预算还剩多少 | 首页一眼看到金额，点一下进入明细 |
| 查找某次购买 | 找到金额、日期和备注 | 搜索、日期与分类筛选可组合使用 |
| 商品退款或账户互转 | 正确记录资金变化 | 退款关联原账单；转账不重复算支出 |
| 几天没记后回来 | 直接继续，不被“断签”打击 | 没有连续签到压力，支持补记 |

### 2.3 暂不服务的需求

首版不覆盖企业报销、家庭多人协作、证券投资、借贷核算、信用卡账单管理、多币种与税务。产品不提供投资或理财建议。

## 3. 核心体验：一笔记录，一点变化

### 3.1 30 秒体验脚本

1. 用户打开应用，看到“先记下今天的一笔”，可直接开始。
2. 点击“记一笔”，数字键盘展开，支出为默认类型。
3. 输入 `18.50`，选择“餐饮”，点击保存。
4. 金额立即计入本月；底部出现“已记下 ¥18.50 · 餐饮”，附“撤销”。
5. 首页小岛出现第一株植物，反馈不到一秒，可直接继续操作。
6. 用户点“看看本月”，看到净支出、餐饮支出和刚记下的记录。

首次体验完成后，再通过非强制入口介绍预算、账户和模板。无需先填写昵称、工资、预算或账户余额。

### 3.2 三条体验红线

- 记一笔不需要先逛小岛、领取奖励或完成任务。
- 看到“保存成功”即代表数据已经持久化；保存失败不得显示成功。
- 统计结论只能来自已记录的数据，不推断用户真实的全部财务状况。

## 4. 信息架构与页面

底部四个导航：首页、明细、统计、我的。全局主操作“记一笔”保持容易触达，避开系统手势区。

| 页面 | 首屏内容顺序 | 主要操作 |
| --- | --- | --- |
| 首页 | 本月净支出 → 预算状态（设置后显示）→ 记一笔 / 常用模板 → 今日记录 → 小岛卡片 | 记账、继续记、查看本月明细、打开小岛 |
| 明细 | 当前日期范围 → 搜索与筛选 → 按日分组的账单 | 查找、编辑、删除、发起退款 |
| 统计 | 月份 → 收支摘要 → 分类分布 → 支出趋势 → 月度故事 | 切换月份、查看对应明细 |
| 我的 | 数据备份状态 → 账户与分类 → 模板与预算 → 显示与隐私设置 | 维护基础信息、导入导出、关闭趣味模式 |
| 记账面板 | 支出 / 收入 / 转账切换 → 金额 → 分类 → 日期与账户 → 备注 → 保存 | 新增记录，切换“保存后继续记” |

首页固定展示当前自然月。明细和统计各自显示明确的日期范围，不把隐藏筛选带回首页。切换页面时保留各页面本次浏览的筛选状态。

### 4.1 首页布局要求

- 核心金额、主操作无需滚动即可看到。
- 未设置预算时不显示空进度条，用低干扰入口“设置本月预算”。
- 小岛卡片位于核心记账信息之后；关闭趣味模式后该区域收起。
- 新用户展示真实空状态，不把演示账单混入正式账本。
- 今日没有记录时显示“今天还没有记录”，允许直接补记过去日期。

### 4.2 记账面板布局要求

- 手机上使用底部全屏或接近全屏的面板，金额区与保存按钮不被键盘遮挡。
- 默认支出、今天、默认账户；分类初始未选中，避免静默沿用错误分类。
- 常用分类先展示，展开后查看全部；分类选中不自动提交。
- 备注、日期和账户是次级操作，不抢占数字输入空间。
- 支出和收入使用各自分类；转账切换为转出账户与转入账户。
- 本次输入有改动时，手势关闭或返回需要确认是否放弃；应用异常重启不承诺恢复未保存内容。

首版不接支付平台，不读取短信，不自动扣款，也不承诺自动获取完整流水。

## 6. P0 详细需求

### 6.1 新增记录

**必填：** 类型、金额、分类（收入 / 支出）、发生日期、账户。日期与账户可使用清楚可见的默认值。备注选填，最多 200 字。

- 金额必须大于 0，最多两位小数，单笔上限为 `99,999,999.99` 元。
- 输入 `18.` 可在保存时规范为 `18.00`；超出两位小数直接提示，不静默四舍五入。
- 日期默认今天，可补记过去日期；首版不保存未来账单。
- 不填写分类时，保存按钮给出就近提示“选一个分类”；不要默认为“其他”。
- 首次使用自动提供“日常账户”，期初余额为 0，可随时改名。
- 默认账户停用后，要求选择新默认账户，不继续写入停用账户。
- 点击保存后立即锁定本次提交，防止双击、回车与重试产生重复账单。
- 保存失败保留本次输入，允许重试；失败记录不改变余额、统计或小岛进度。
- 默认保存后返回原页面。“保存后继续记”由用户开启并记住偏好。
- 连续记账时保留类型、日期、账户；清空金额、分类和备注。日期明显显示，用户不易把补记状态误认为今天。
- 新记录成功后，列表、首页、余额与统计同步更新。

**验收场景：** 新用户不注册，输入 `18.50` 并选择餐饮即可完成首笔支出；没有额外的强制资料填写步骤。

### 6.2 常用模板

- 从账单详情选择“存为常用”，或者在模板管理中新增。
- 模板保存名称、类型、金额、分类和账户；不保存账单日期。
- 点击模板打开带入内容的记账面板，日期为今天，用户确认保存后才生成账单。
- 模板属于支出或收入；首版不支持转账和退款模板。
- 首屏最多展示 4 个模板，其余从“全部常用”进入；排序由用户调整。
- 关联分类或账户停用时，模板标记“需要更新”，要求重选后保存。
- 默认不为用户生成虚构金额的模板。

### 6.3 明细、搜索与修正

- 按发生日期倒序分组；同日按创建时间倒序展示。
- 每项显示分类、金额、账户、备注摘要；转账、退款有文字类型标记。
- 支持月份或自定义日期范围、类型、分类、账户的组合筛选。
- 搜索备注、分类名和账户名；金额通过金额范围筛选，不做含义不明的模糊匹配。
- 日汇总分别显示净支出与收入；转账不进入日收支。
- 从统计数字进入明细时自动带入相同月份、分类和类型口径，并显示筛选标签。
- 编辑后按新日期、账户和分类重新计算；不留下旧值的重复影响。
- 原类型不能直接改成其他类型；需要删除后重记，避免退款关联与账户语义混乱。
- 删除前显示金额与日期；有关联退款时提示将一并删除的退款笔数及金额，确认后整组删除。
- 新增、编辑和删除后提供 10 秒“撤销”，撤销作为一次完整操作恢复对应余额与统计。连续操作时只保留最近一次可撤销操作。
- 撤销前检查受影响记录是否已被后续操作或其他标签页修改；如有冲突，提示无法撤销，不覆盖新数据。整库恢复或清空后，先前的撤销入口立即失效。
- 退款单独删除后，恢复原支出的可退款额度。

### 6.4 分类

默认支出分类：餐饮、交通、购物、住房、生活缴费、娱乐、医疗、学习、人情、其他。默认收入分类：工资、奖金、兼职、其他。

- 新增分类只要求名称，可选简单图标；同一类型下不能重名。
- 分类改名同步影响历史展示；分类关联使用稳定标识，避免改名导致记录丢失。
- 关闭或停用分类不删除历史账单；新增面板不再展示该分类。
- 已被账单或模板使用的分类不提供直接永久删除，改为停用。
- 退款沿用原支出的分类；原支出重新分类后，关联退款一起归入新分类。

### 6.5 账户与转账

- 支持新增、改名、排序、设置默认和停用账户；名称不能重复。
- 首版只有手工账户。名称与图标不代表已接入银行或支付平台。
- 期初余额是本账本中该账户所有流水之前的余额，可以为负数，默认 0。
- 修改期初余额只影响账面余额，不生成收入或支出，也不改变历史统计。
- 不知道期初余额时可以保持 0；界面注明“手工账面余额，可能与实际余额不同”。
- 转账要求转出、转入两个不同的启用账户及正数金额；一笔操作同时更新两边余额。
- 转账不进入收支统计和预算。手续费如需记录，另记一笔支出。
- 退款默认退回原账户；允许选择另一个启用账户，实际退款到账账户获得余额。
- 已被历史账单使用的账户只可停用；历史余额、转账与退款关联继续保留。
- 不因账面余额不足而禁止记账，避免未知期初余额影响真实记录。

### 6.6 退款

- 必须从原支出发起；首版不支持无原账单的独立退款。
- 可以分多次退，但未删除退款的累计金额不能超过原支出金额。
- 退款日期不能早于原支出日期，也不能晚于今天。
- 退款是独立记录并关联原账单；详情双向可跳转，原支出显示“已退 ¥X”。
- 退款使用正金额，通过类型表达资金方向，不能记录成收入。
- 编辑原支出金额时，不得低于累计退款；编辑日期时不得晚于任何关联退款日期。
- 原支出和退款发生在不同月份时，按各自发生日期分别统计，不回写原月份。

### 6.7 总预算

- 用户主动设置大于 0 的本月总预算；不要求填写收入，不自动建议“合理预算”。
- 预算按自然月保存。首次设置后，后续月份自动沿用最近一个已配置月份的额度及启用状态；沿用启用额度时标明“沿用上次预算”。停用后维持停用，直到用户重新开启。
- 修改只影响所选月份；历史月份可查看但首版不补设或修改预算。
- 当月净支出计入预算。首页展示“本月净支出 / 月预算”和剩余金额。
- 达到 80% 时出现“本月预算已使用 80%”；达到或超过 100% 时显示剩余 0 或“超出 ¥X”。
- 不拦截继续记账，不发送羞辱性提醒，不把超支与小岛成长关联。
- 跨月退款可能让本月净支出为负、剩余预算大于设置额；清楚标注“本月退款使可用预算增加”。
- 未设置预算时仍可完整使用记账和统计。

### 6.8 统计与月度故事

统计默认当前自然月，可切换有记录的历史月份。

| 模块 | 展示内容 | 特殊状态 |
| --- | --- | --- |
| 收支摘要 | 支出总额、退款总额、净支出、收入、收支结余 | 净支出允许负数；每个指标可展开口径说明 |
| 分类分布 | 各分类原始支出金额及其占支出总额的比例；另列退款和净额 | 支出总额为 0 时不计算占比，展示空状态 |
| 每日趋势 | 每日净支出，可切换收入；金额轴从 0 延展 | 退款形成负值时展示负向柱形；不截断负数 |
| 月度故事 | 记录天数、累计记录、主要支出分类、预算状态 | 数据不足时只陈述已有事实 |

**月度故事规则：**

- 通过确定性模板生成，首版不依赖生成式 AI。
- 当月可随时查看，标题为“本月进行中”；结束后显示完整月份。
- 示例文案：“这个月，你留下了 12 天的记录。餐饮是支出最多的分类。”示例数字仅用于原型，不进入真实账本。
- “记录天数”按该月包含有效收入或支出的不同发生日期计数；转账与退款不增加天数。
- “支出最多的分类”按原始支出金额计算；并列时展示并列，未记录支出则省略。
- 没有记录时显示“从一笔记录开始认识这个月”，不生成“你没有花钱”等结论。
- 不评价消费好坏，不推断收入水平，不把记录覆盖率说成真实财务完整度。
- 首版不做月环比、节省金额或预测，避免部分月份对比产生误导。

## 7. 趣味机制

### 7.1 小岛成长

小岛是一张有留白的 2D 插画。用户记录生活，场景逐步丰富。首版只有一个主题和 4 次解锁，不做可自由摆放的建造游戏。

| 阶段 | 解锁条件 | 场景变化 |
| --- | --- | --- |
| 初始 | 打开产品 | 小岛、海面和一条小路 |
| 初记 | 首笔有效收入或支出 | 出现第一株植物 |
| 三日 | 累计 3 个不同记账日 | 路边增加长椅 |
| 七日 | 累计 7 个不同记账日 | 增加树与鸟 |
| 十四日 | 累计 14 个不同记账日 | 点亮小灯塔，进入完整场景 |

- “不同记账日”按账单发生日期计，不要求连续；补记可以计入。
- 金额大小、每天账单数量、是否超支都不影响成长。
- 转账、退款、示例数据不触发成长；只浏览页面也不产生虚构进度。
- 解锁状态单独持久化，已获得的装饰不因删除账单或中断记账而消失；当前记录天数仍按有效数据如实显示。
- 每个阶段只解锁一次；删除再新增同一天的记录不会重复领取。
- 成长反馈在保存成功后出现，不盖住金额与撤销入口，不要求点击“领取”。
- 关闭趣味模式后停止显示小岛和成长动画，已解锁状态保留；重新开启可继续查看。
- 首版到达完整场景后继续展示岛屿和月度故事，不无限增加任务。

| 时机 | 推荐文案 | 行为 |
| --- | --- | --- |

## 8. 金额与统计规则

### 8.1 基础定义

- 首版币种固定为人民币。所有金额内部使用“分”的整数计算，展示最多两位小数。
- 一笔记录只归属一个账户；转账是同一笔业务的双账户变化，不生成两笔可独立编辑的账单。
- 发生日期以账本时区 `Asia/Shanghai` 的自然日为准，保存为明确日期；系统创建和修改时间独立保存。
- 本月为自然月第一天至最后一天。记录按发生日期归属月份，补记不按创建时间算进今天。
- 删除记录不进入任何正式汇总；撤销后重新进入。

### 8.2 统一计算公式

```text
某期间支出总额 = 该期间所有有效支出的金额之和
某期间退款总额 = 该期间所有有效退款的金额之和
某期间净支出 = 支出总额 - 退款总额
某期间收入 = 该期间所有有效收入的金额之和
某期间收支结余 = 收入 - 净支出

某账户账面余额 = 期初余额
                 + 收入 - 支出 + 到账退款
                 + 转入 - 转出

本月预算已用金额 = 本月净支出
本月预算剩余 = 本月预算 - 本月净支出
预算进度图形 = 将（净支出 / 预算）限制在 0% 到 100% 后绘制
预算旁的实际金额与实际使用比例不截断，超过 100% 时明确显示超出部分
```

转账不影响全账本收支结余。月度结余只表达已记录收入与净支出的差额，不等于可花现金、资产或储蓄率。

净支出为负时照常展示，预算图形为 0%，旁边以退款说明代替负的进度百分比。分类分布使用原始支出占比，避免混用净额造成负占比或超过 100%。

### 8.3 必须通过的样例

| 操作 | 预期结果 |
| --- | --- |
| A 账户期初 1,000 元，B 账户期初 0 元；A 支出 100 元、收入 1,000 元、收到关联退款 30 元，再从 A 转给 B 200 元 | A 余额 1,730 元，B 余额 200 元；全账本收入 1,000 元、支出 100 元、退款 30 元、净支出 70 元、结余 930 元 |
| 10 月支出 100 元，11 月退回 30 元，期间没有其他收支 | 10 月净支出 100 元；11 月支出 0、退款 30、净支出 -30 元；两月合计净支出 70 元 |
| 上述 11 月预算设为 1,000 元 | 剩余预算 1,030 元，图形进度为 0%，显示退款说明 |
| 原支出 100 元，已退 30 元，再尝试退 80 元 | 阻止保存，提示最多还可退 70 元 |
| 把已退 30 元的原支出改为 20 元 | 阻止保存，要求先处理关联退款 |
| 把一笔 9 月的支出补记于 11 月 | 归属 9 月，11 月收支不变 |
| 从 A 转给 A，或金额为 0 | 阻止保存，定位到错误字段 |
| 删除一笔含两次退款的支出，然后撤销 | 确认后整组删除；撤销一次恢复原支出、两笔退款和全部余额变化 |
| 连点保存、刷新后重试同一已提交请求 | 最终只有一条业务记录 |

## 9. 数据、隐私与恢复

### 9.1 本地优先

- 无需注册即可使用，账本默认只保存在当前浏览器和当前设备。
- 首次成功保存后，用一次可关闭的提示说明“数据保存在本机，建议定期导出备份”。
- PWA 首次加载成功后缓存必要页面与资源，断网可打开、查询和新增记录。
- 更换设备、清除浏览器数据或使用隐私模式可能使本地数据无法保留；在备份入口和相关首次使用位置说明。
- 不把 PWA 的安装成功等同于已完成数据备份。
- 浏览器不支持可靠持久化或存储不可写时，不能假装保存成功；明确提示并阻止开始真实记录。
- 不承诺依赖浏览器自动跨设备同步。首版跨设备迁移通过用户主动导出和恢复完成。

### 9.2 备份、恢复与导出

- **JSON 完整备份：** 包含账单、退款关联、账户、期初余额、分类、预算、模板、小岛解锁状态、设置及格式版本，可完整恢复。
- **CSV 明细导出：** 包含稳定记录 ID、类型、金额、日期、分类、账户、转入账户、备注、退款关联 ID 等字段；使用适合中文表格软件的编码。CSV 用于查看与分析，不承诺完整还原产品状态。
- 导出默认覆盖全部数据；按筛选条件导出时明确标注“部分明细”。完整备份始终导出全部账本。
- 备份文件默认未加密，导出前简短说明“文件包含账务信息，请妥善保存”。
- 首版只支持本产品 JSON 备份的恢复，不支持任意银行、支付平台或第三方 CSV 的导入。
- 恢复流程：选择文件 → 本地校验 → 预览记录数、日期范围与覆盖范围 → 为现有账本生成安全备份 → 用户确认替换 → 一次性完成。
- 恢复采用替换模式，不把重复导入当成新增。替换前必须确认安全备份文件已生成并由用户保存；备份未完成不得覆盖现有数据。
- 文件损坏、未知版本、重复 ID、缺失关联、金额非法或累计退款超额时，整包拒绝导入，不产生部分数据。
- 恢复失败时保留原账本；恢复成功后记录导入时间，并提示继续保留原备份文件。
- 展示最近一次成功导出完整备份的时间；累计新增记录且距上次完整备份超过 7 天时，显示可关闭的轻提示，每 7 天最多一次。

### 9.3 隐私与删除

- 提供首页金额隐藏开关，记住用户选择；统计和明细页同步隐藏金额，用户主动点开单笔时可临时查看。
- 提供减少动态效果开关，并遵循系统减少动画偏好。默认无音效。
- 首版不上传账单金额、备注、账户名称和消费明细，不接广告追踪。
- 如开展试用埋点，需用户知情选择；事件不包含账单内容或可还原金额的信息。
- “清空全部数据”显示具体范围、建议先备份，并要求输入确认文字；清空账单、配置与小岛进度，不在应用内保留隐藏副本。用户已导出的文件需由用户自行管理。
- 单次账单的 10 秒撤销不适用于全量清空与整库恢复，必须在操作前说明。

## 10. 视觉与交互规范

整体气质：轻松、温暖、克制。小岛提供趣味，数字和操作保持清楚。

- 底色采用暖白，搭配低饱和海蓝或草绿；重要金额使用高对比深色。
- 收入、支出与退款同时用文字、符号和色彩区分，不依赖红绿颜色辨识。
- 金额使用等宽数字，列表小数位对齐，单位保持一致。
- 手机关键触控区域不小于 44 × 44 CSS 像素；桌面支持键盘焦点和明确的焦点样式。
- 普通文字对比度至少 4.5:1；大字号至少 3:1。
- 适配 320 CSS 像素宽屏幕与大字号；主按钮、金额和分类不被裁切。
- 常规保存反馈动画约 200–400 毫秒；成长反馈不超过 800 毫秒，可被继续操作打断。
- 不使用晃动催促、全屏撒花、自动播放声音或强制领奖弹窗。
- 浅色主题为首版基础；深色主题列入后续，不影响主流程交付。

## 11. 关键异常与空状态

| 状态 | 应有表现 |
| --- | --- |
| 首次打开 | 明确的“记第一笔”入口，无假数据，无强制注册 |
| 查询无结果 | 显示当前筛选，可一键清除条件 |
| 某月无记录 | 金额为 0，并说明仅代表没有记录；不说“这个月没花钱” |

| 存储空间不足 | 提示保存失败，保留当前输入并提供备份入口，不提示成功 |
| 多个标签页同时操作 | 禁止用旧快照覆盖全库；逐笔保存，其他页面收到变化后刷新；正在编辑的同一记录已变化时提示冲突并要求重新载入 |
| 退款关联账户停用 | 历史关联保留，新退款要求选择可用的到账账户 |
| 模板依赖已停用分类 | 模板标记需要更新，不静默改成其他分类 |
| 恢复文件异常 | 指明可理解的失败原因，原数据不变 |
| 用户关闭趣味模式 | 首页回到纯记账布局，主流程和数据能力完整可用 |

## 12. 支撑实现的最小数据模型

本节规定业务边界，不锁定具体技术框架。

| 对象 | 关键内容 | 约束 |
| --- | --- | --- |
| 账本 | 标识、币种、时区、数据格式版本 | 首版一个账本，CNY，Asia/Shanghai |
| 账户 | 标识、名称、展示类型、期初余额、排序、是否停用 | 历史关联稳定；默认账户必须启用 |
| 分类 | 标识、支出 / 收入、名称、图标、排序、是否停用 | 同类型名称唯一；退款继承原支出分类 |
| 记录 | 标识、业务类型、正整数金额分、发生日期、账户、分类、备注、创建及修改时间、修订版本、提交标识 | 转账包含目标账户；退款包含原支出 ID；按类型校验字段 |
| 月预算 | 年月、额度、是否启用、是否沿用 | 一个自然月一个总预算 |
| 模板 | 名称、收入 / 支出类型、金额、分类、账户、排序 | 不携带发生日期 |
| 趣味进度 | 已解锁阶段、首次解锁时间、趣味开关 | 和账务汇总分离，已解锁阶段不倒退 |
| 偏好与备份信息 | 默认账户、继续记偏好、金额隐藏、减少动画、上次完整导出时间 | 随 JSON 备份恢复 |

保存、编辑、删除及撤销须作为完整事务处理：账单关联、转账两端及退款额度保持一致。余额与统计以有效记录重新聚合为准；即使使用缓存，也必须能从记录重算得到同一结果。

## 13. 成功指标与验证计划

以下数值是首轮试用的内部目标，未经真实样本验证，不代表行业基准或产品已有表现。

### 13.1 核心观察

**主要观察指标：** 试用第 2 周，至少在 3 个不同自然日完成有效记账的用户比例。它衡量重复使用，不能代替真实消费的完整记录率。

首版不以记账金额、单日账单数量或打开小岛次数作为核心成功指标，避免引导不必要消费或无意义操作。

| 指标 | 定义 | 首轮目标 |
| --- | --- | --- |
| 首次记账完成率 | 在引导页点击开始的用户中，成功保存首笔真实记录的人数占比 | ≥80% |
| 新账单录入效率 | 从打开记账面板到持久化成功，限标准支出任务 | 熟悉后中位数 ≤5 秒，90 分位数 ≤12 秒 |
| 模板录入效率 | 从点击已有模板到保存成功 | 熟悉后中位数 ≤3 秒 |
| 第二周重复记账 | 首周完成首笔的用户中，在试用第 8–14 天内至少 3 天记账的人数占比 | ≥40% |
| 统计理解率 | 不经解释，正确回答指定月份净支出与最大支出分类的人数占比 | ≥80% |
| 可恢复性 | 用正式 JSON 备份在空环境恢复后，余额、统计和关联正确 | 必须全部通过 |
| 严重数据问题 | 观察到的数据丢失、重复保存、错误余额、半笔转账 | 发布前为 0；试用出现即暂停扩大试用并修复 |

### 13.2 验证方式

1. 招募 5–8 名符合目标行为的用户做可用性测试，任务包括首次记账、连续补记、找账、退款、查预算和备份恢复。
2. 首轮重点记录任务完成、耗时、误操作与用户原话，不将小样本结果包装成市场结论。
3. 核心任务通过后，邀请约 20–30 人自愿进行 14 天真实试用；目标数值用于方向判断，小样本不足以证明长期留存提升。
4. 试用用户可关闭小岛，访谈其选择原因；比较操作干扰与主观感受，不直接把自选组差异解释为因果。
5. 若用户能快速记账但很少看统计，先检查统计是否回答问题；若趣味反馈干扰操作，缩小反馈强度。

如收集匿名产品事件，仅记录“面板打开、保存成功 / 失败、撤销、统计打开、故事打开、趣味开关、完整备份导出、恢复成功 / 失败”等必要事件，以及不含账务内容的耗时与错误类别。未同意分析采集的用户仍可完整使用产品；试用指标可通过自愿测试记录获得。

| D：试用 | 14 天试用记录、问题清单、下一版范围 | 数据可靠性达标，完成核心假设复盘 |

### 14.1 发布必须满足

- 首次使用可以直接记账，收入、支出、转账、退款四类业务都有正确流程。
- 首页、明细、统计、预算与账户余额对同一批数据给出一致结果。
- 本文金额样例、跨月退款、记录编辑与整组撤销全部通过。
- 保存成功的数据在刷新、断网重开和应用重启后仍能读到。
- 快速重复点击与多标签操作不产生重复记录、丢失更新或单边转账。
- 完整备份能在空环境还原；错误文件不会破坏现有账本。
- 用户关闭小岛后仍有完整、清楚的记账界面。
- 小屏、键盘弹出和大字号下可完成记录；金额不只靠颜色表达。
- 删除、清空、恢复等行为有与影响范围相符的确认和提示。

## 15. 商业化与后续边界

首版不接广告、不做付费墙，先验证使用价值。记账、查账、修改、完整备份与数据导出不作为后续锁定用户数据的手段。

如验证出持续使用价值，再考虑可选主题、装饰或云端服务。定价、付费意愿和服务成本需要单独验证，本版不预设收入规模。小岛成长不通过消费金额、抽奖或付费补签驱动。

## 16. 待确认事项

为形成可评审的首稿，本文已采用以下默认假设；调整它们不妨碍先评审核心体验。

| 事项 | 当前假设 | 改变后主要影响 |
| --- | --- | --- |
| 首发平台 | 手机优先 Web / PWA | 原生 App 或小程序需要重新评估存储、离线、分发与交互能力 |
| 目标人群 | 个人日常收支，记账意愿较强但容易中断 | 家庭、企业、重度财务用户需要不同账务模型 |
| 趣味风格 | 轻量治愈的小岛，默认开启，可随时关闭 | 可换成更克制的生活地图或其他主题，账务功能不变 |
| 数据方式 | 本地优先、无需登录、用户主动备份 | 云端账号与同步会增加服务端、隐私和冲突处理范围 |
| 首版投入 | 完成全部 P0，阶段性交付，不先估工期 | 若需更快验证，可先做可点击原型，真实记账发布门槛仍保留 |

下一项交付建议：基于本稿制作“首页 → 记一笔 → 明细 → 统计”的可点击原型，同时验证记账速度和小岛反馈是否让人愿意回来。
